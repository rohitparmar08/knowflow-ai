# Deployment guide

KnowFlow AI has three pieces: **Postgres with pgvector**, the **Django API**, and a **static React build**.

## 0. Run everything locally with Docker

```bash
cp .env.example .env        # fill SECRET_KEY, DB_PASSWORD, LLM_API_KEY
docker compose up --build
```
Frontend: http://localhost:3000 · API health: http://localhost:8000/api/health/

## Recommended free setup: Neon + Render + Vercel

Everything below runs on free tiers and needs no credit card. Embeddings are computed by the Gemini API, so the API server needs very little memory.

**1. Database (Neon).** Create a project, open **Connect**, turn connection pooling off and copy the `postgresql://...` string. Keep it private. pgvector is available out of the box; the first migration enables it.

**2. Backend (Render).**
1. In Render choose **New → Blueprint** and select this repository. `render.yaml` defines the web service (Python, free plan, `backend/` as root directory, health check `/api/health/`).
2. Fill in the values Render asks for:

   | Name | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string |
   | `LLM_API_KEY` | your Gemini API key (also used for embeddings) |
   | `ALLOWED_HOSTS` | the Render hostname, for example `knowflow-api.onrender.com` |
   | `CORS_ALLOWED_ORIGINS` | your Vercel URL, for example `https://knowflow-ai.vercel.app` (add it after step 3) |
   | `CSRF_TRUSTED_ORIGINS` | same as above |

   `SECRET_KEY` is generated by Render. Migrations run on every start.
3. Check `https://<your-service>.onrender.com/api/health/` returns `{"status": "ok"}`.

**3. Frontend (Vercel).** Import this repository, set **Root Directory** to `frontend`, and add the environment variable `VITE_API_URL=https://<your-service>.onrender.com/api`. Deploy, then put the Vercel URL into `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` on Render and let it redeploy.

Free tier behaviour: the Render service sleeps after about 15 minutes without traffic, so the first request afterwards takes around a minute. Its disk is not persistent, so uploaded source files disappear on restart while their chunks stay in the database (asking questions keeps working; "reprocess" needs the file to be uploaded again).

## 1. Other hosting options

| Option | Notes |
|---|---|
| Railway / Fly.io | Paid or credit based. Attach a persistent volume and set `MEDIA_ROOT` to it. |
| Your own VM (Oracle Cloud free ARM, a small VPS) | `docker compose up -d` behind Caddy/nginx for HTTPS. |
| Local embeddings | Set `EMBEDDING_PROVIDER=local` and install `requirements-local.txt`. This needs roughly 2 GB of RAM for PyTorch and the model. |

**Database:** any Postgres with pgvector. Neon and Supabase both offer it on a free tier (the first migration runs `CREATE EXTENSION vector`; if your provider needs it enabled manually, do that in its dashboard first).

**Frontend:** deploy `frontend/` as a static site (Vercel, Netlify, Cloudflare Pages) with build command `npm run build`, output `dist`, and the env var `VITE_API_URL=https://<your-api-host>/api`. Add a rewrite of all paths to `/index.html` (React Router); `frontend/vercel.json` already does this for Vercel.

## 2. Required environment variables (API)

| Variable | Example | Why |
|---|---|---|
| `SECRET_KEY` | long random string | App refuses to start without it when `DEBUG` is off |
| `DEBUG` | `False` | Default is already False |
| `ALLOWED_HOSTS` | `api.example.com` | Host header allow-list |
| `CORS_ALLOWED_ORIGINS` | `https://app.example.com` | Your frontend origin(s), comma separated |
| `CSRF_TRUSTED_ORIGINS` | `https://app.example.com` | Same |
| `DATABASE_URL` | `postgres://user:pass@host/db` | Or use the `DB_*` variables |
| `LLM_API_KEY` / `LLM_MODEL` | Gemini key / model name | Check the model name exists for your key in Google AI Studio |
| `EMBEDDING_PROVIDER` | `gemini` (default) or `local` | Gemini embeddings use `LLM_API_KEY` unless `EMBEDDING_API_KEY` is set |
| `RAG_MAX_DISTANCE` | `0.8` | Relevance cut-off. Check it with `python manage.py rag_probe` after changing the embedding model |
| `TRUST_PROXY_SSL_HEADER` | `True` | When the host terminates TLS for you |
| `SECURE_SSL_REDIRECT` | `True` | Optional, after HTTPS works |
| `MEDIA_ROOT` | `/data/media` | Point at a persistent disk |
| `THROTTLE_ASK`, `THROTTLE_AUTH` | `20/min`, `10/min` | Rate limits |

## 3. Release checklist

1. `python manage.py check --deploy` shows no issues with your production env vars.
2. `GET /api/health/` returns `{"status": "ok"}`.
3. Register → upload a small PDF → wait for status `ready` → ask a question → answer has `[1]` citations.
4. Frontend loads, login works, no CORS errors in the browser console.

## Known limitations

- Documents are processed synchronously inside the upload request. Large PDFs can take a while; the Gunicorn timeout is 120 s on Render (180 s in Docker), and Gemini's free tier rate-limits embedding calls.
- Uploaded files are served only by the API (not via `/media/` in production), so the `file` URL in API responses is not a public download link.
- Retrieval is vector-only (no keyword/hybrid search yet).
